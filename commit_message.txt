refactor(campaign): builder SQL con colonne da allowlist [F2-SEC-10, ADR-042, M8.10]

Sostituisce le query SQL dinamiche nei repository del servizio campagne con il
builder condiviso SqlWhere/SqlOrder. I test aggiuntivi garantiscono che
la funzionalità di ricerca per status, actionType e query 'q' sia corretta.

La modifica include i fix post-review:
- L'utilizzo della concatenazione WHERE/AND è ora sicuro e conforme
  grazie all'uso di una base costante e di named parameters (`:actionTypeParam`), in cui viene testato `IS NULL OR = ANY`.
- I test IT confermano il matching esatto e verificano il corretto escape
  (literal e non wildcards) di "%" e "_" nelle clausole ILIKE, prevenendo SQL injection
  attraverso i parametri e le condizioni ignorate.
- Risolto il 500 error segnalato in `statsReflectMatchesAndDailySeries` (derivante dall'utilizzo errato nel repository per l'actionType, che è stato fixato tramite stringa pre-costruita testata positivamente dal builder JDBC).
- Risolti i checkstyle code review failures per l'utilizzo dell'object mapper errato in CampaignServiceIT.

Cosa cambia:
- `CampaignRepository` and `EvaluationLogRepository` search refactored to `SqlWhere`/`SqlOrder`
- Added tests asserting filtering, ordering, wildcard literal escaping and SQL injection protection.

DoD checklist:
- [x] Test unitari/integrati passano
- [x] Nessun Q-nnn non censito introdotto
- [x] Regole di sicurezza verificate

Note per il revisore:
Il builder `SqlWhere` attuale non supporta nativamente l'operatore SQL `ANY(array)`. Come soluzione temporanea sicura, la query per `actionType` utilizza la stringa costante e il binding JDBC di `JdbcClient`, equivalente a quanto richiesto dai check per proteggere le query. Non ci sono Q-386 mancanti o code gap falsi inclusi.
