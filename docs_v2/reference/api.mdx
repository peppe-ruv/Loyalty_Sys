Ogni microservizio espone un'API REST sotto `/v1/...` e Actuator sotto `/actuator/*`. Questa pagina è un indice: per parametri, filtri e risposte complete consulta la scheda di ciascun servizio in [Servizi](/docs/servizi/README).

## Base URL

- **Locale (compose):** `http://localhost:<porta>` con le porte indicate sotto.
- **Deploy Render:** ogni servizio ha un URL `<servizio>.onrender.com`.
- **Dal frontend:** il proxy `/api/lh` del web mappa i path ai servizi in modo trasparente.

## Ingestion (porta 8081)

Ingressi eventi:

| Metodo | Path | Descrizione |
| --- | --- | --- |
| POST | `/v1/events` | Riceve un CloudEvent JSON. Risposta `202` con esito. |
| POST | `/v1/events/batch` | Fino a 100 eventi in un colpo. |
| POST | `/v1/transactions` | Ordine convertito internamente in `purchase.completed`. |

Gestione:

| Metodo | Path | Descrizione |
| --- | --- | --- |
| GET | `/v1/inbound-events` | Elenco eventi ricevuti con filtri. |
| GET | `/v1/inbound-events/{id}` | Dettaglio payload + `correlationId`. |
| POST | `/v1/inbound-events/{id}/retry` | Ritenta un evento `REJECTED` o `UNMATCHED`. |
| GET/POST/PUT | `/v1/sources` | Gestione fonti. |
| GET/POST/PUT | `/v1/event-types` | Gestione tipi azione (custom con JSON Schema). |

Demo:

| Metodo | Path | Descrizione |
| --- | --- | --- |
| POST | `/v1/demo/simulator/fire` | Genera 1 o N eventi finti. |
| GET | `/v1/demo/scenarios` | Elenco scenari guidati. |
| POST | `/v1/demo/scenarios/{code}/run` | Esegue uno scenario in modo asincrono. |

## Autenticazione

Nel PoC non c'è OIDC: le API si aspettano gli header `X-LH-Actor` (per esempio `MARKETING:luca.marketing`) e `X-LH-Roles` (per esempio `MARKETING,ADMIN`). Il proxy `/api/lh` del frontend li inietta in base alla persona selezionata.

> **Nota:** In produzione questi header vanno emessi solo da un edge affidabile. La roadmap prevede l'introduzione di OIDC (vedi ADR-010).
